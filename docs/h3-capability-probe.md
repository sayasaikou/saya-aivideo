## 二、被推翻 / 修正的四个认知

1. 🔴 **turbo 提速工具链先说错了**。曾估「15 秒片 876 s → 7~8 分钟」，**实测只值约 21%**。
   错因：按「步数 8/20」线性外推，而 H3 是**两阶段**结构：
   - 第一阶段（低分辨率）吃步数，15 秒片里占 5m11s（≈15.5 s/步）
   - 第二阶段（目标分辨率）**固定 3 步**，占 6m39s（≈2m13/步）——步数改了它也不动
   - ⇒ 能省的只有第一阶段：14m36s → 约 11m29s
2. **单阶段反而更慢**：全分辨率 24 s/步，而低分辨率只要 4 s/步。
3. **H3 第二阶段自带 turbo**：`pipeline.py` 写死 `H3_REQUIRED_TURBO_TOKENS = ("minimax_h3","fl2v","turbo","4step","v0.1")` —— 第二阶段永远挂自带的 FL2V 4 步 turbo，并主动把别的 turbo LoRA 关掉。两个 LoRA 不是打架，是**分工**。
4. **turbo 两阶段在当前配置下必崩**：多挂 1.3 GB LoRA 权重 ⇒ 显存不够 ⇒ VAE 解码 conv3d 处 `CUDA out of memory`（试过分块第二阶段，同位置仍崩）。**已按下**，不再碰。

### 八·补 · 「字幕乱来」已实测复现（工具链抽帧查证，不是猜）

抽 `ceobe-audiodriven-9s.mp4` 五帧跑本地 OCR，**帧上真烧进去了中文字**，而且是乱码：

| 帧 | OCR 结果 |
| --- | --- |
| t=1s | 我们就是这快径了 |
| t=3s | 你是今也着了一个人会都都的好吗 |
| t=5s | 吧为一个扳可以好缺叫 |
| t=7s | （无） |
| t=9s | 他就就是在他不什么么了 |

**推断成因（有对照）**：T1.1 用的是官方台词标签 `(S1) <d>[Chinese] …</d>`，抽帧 OCR **一个字都没识别到**；而 T2.2 的 job.json 提示词里写着 `They speak the supplied audio line in Chinese`（明写“说中文”），模型就把台词**当成画面文字画了出来** —— 扩散模型画字本来就是糊的。

**待验证的假设**：把那句改成不提“in Chinese / 台词”，再显式排除「画面内不得出现任何文字、字幕、书写符号」，同 seed 重跑一条，看字幕是否消失。

### 八·补2 · 音频侧实测（2026-10-11 晚，回应「捧读感 / 单薄 / 机械底噪」）

| 指标 | 官方 cn_003 | AI 克隆（旧参考） |
| --- | --- | --- |
| 静音段底噪 | −92 dB（有底噪） | **−180 dB（数字静音）** |
| F0 健量（5–95%） | 10.1 半音 | 11.2 半音 |
| 节奏 CV（音节间隔） | 0.811 | 0.968 |
| 8–12 kHz 能量占比 | 1.138% | 0.521% |
| 12–16 kHz 能量占比 | 0.071% | 0.042% |

- ⇒ **「机械底噪」不是加性噪声** —— AI 输出的静音段是**数字静音**（比官方原声还干净）；听感上的「机械」在发声段的音质/音色本身。
- ⇒ **「捧读感」也不是音高太平** —— 克隆的 F0 跨度反而比参考音宽（11.2 vs 10.1）。
- ❓ **「单薄」的线索**：AI 输出 8–16 kHz 能量约为官方的一半。⚠️ **存疑** —— 官方素材是 ~47 kbps 的 mp3（本身有损、会引入高频伪影），AI 是无损 wav，**这个对比被编码污染**，只能算线索。
- ✅ **排除转码嫌疑**：aac 128k 版 vs 源 wav —— F0/节奏逐项完全一致（10.6 半音 / 0.885），14k+ 能量 0.017% vs 0.018% ⇒ 交付用的压片没有可测量损失。
