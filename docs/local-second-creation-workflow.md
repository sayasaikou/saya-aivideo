> **2026-10-08 立** ｜ 目标：16GB 显存笔记本上，本地跑通「半写实二次元角色 → 5~15 秒动态短片」，抽卡为主。
> 本机：**RTX 5080 Laptop 16GB（Blackwell sm_120）** / 32GB 内存 / Windows 11 / ComfyUI 0.36.0 / E 盘剩 1132 GB
> **配套调研**：[AI二创-写实风二次元-中文社区调研-20261008.md]($env:DSH_WORKSPACE\AI视频调研\AI二创-写实风二次元-中文社区调研-20261008.md)（三路调研，41 KB，含全部来源与可信度分级）

## 0. 三句话

1. **风格在首帧定死，视频模型只管"动得对不对"** —— 功夫压在首帧，不在视频模型。
2. **别把每个镜头都交给视频模型** —— 有份 90 秒实拍复盘里，103 个验收单元中 **70 个用本地 H3、28 个完全没用视频模型（生图+代码合成）、5 个用原片**。约 **27% 的镜头根本不需要生成视频**，砍掉它们，16GB 的算力预算才够。
3. **视频段主力已换代：MiniMax H3 > Wan 2.2** —— Wan 2.2 退为"低配 + 中文提示友好"的入门位，AnimateDiff 基本退役（B站作者 12GB 实测验收记录：H3「可以完全取代 Wan 2.2 和 AnimateDiff」）。

## 1. 全链路（五段 · 修正版）

```
[0] 角色资产 ── 三视图 / 定妆照（正面·四分之三·侧·背）＋ 参考音频   ← 新增的一段，最省返工
      ↓
[1] 首尾帧   ── 用参考图锁身份，出每个镜头的首帧（＋尾帧）
      ↓  挑图：构图 · 风格 · 有没有手
[2] 视频段   ── H3 生成（带原生音频）；**不需要动的镜头走"生图+剪辑"**
      ↓  过筛：运动方向 / 崩脸 / 手 / 闪烁
[3] 后期     ── 剪辑点对齐 → 超分 → 音效/口型 → 调色
      ↓
[4] 归档     ── 参数 / 种子 / 模型写进 meta.json
```

**为什么 [0] 单列一段**：社区共识 —— 先出三视图/定妆照，正面用于面部特写、侧背用于转身背影、衣着写完整。
有作者验收记录：「**第一集没锁形象返工 6 次，第二集锁死基本一次过**」。

**为什么 [3] 不是可选项**：行业口径（中文在线 AI 动漫部总经理周立强）把 AI 漫剧精简为
「剧本创作 → 图片生成 → 图转视频 → **后期加工**」四步 —— 后期是被独立列出的第四步，不是附赠。

## 2. 选型（按本机约束排序）

### 2.1 视频段主力：MiniMax H3

| 项 | 规格 |
| --- | --- |
| 发布时间 | 2026-07-31 发布，08-03 开权重（开源） |
| 能力 | **全模态**：文生 / 图生 / 参考生视频 + **原生 32kHz 立体声音轨** |
| 时长 | **4~15 秒** |
| 分辨率 | 768p 原生 → **H3-Regenerate-2K** 重生成到 2K |
| 帧率 | 24 FPS |
| 对话语言 | 11 种（含**中文、日文**） |
| 输入模式 | **FL2VA**（首尾帧，0/1/2 张图）／ **Ref2VA**（全参考：≤9 图 + ≤3 视频 + ≤3 音频） |
| 系统三模块 | H3-Context-IR（理解/改写）→ H3-Base（768p）→ H3-Regenerate-2K |

**为什么它是主力**：带音频（Wan 2.2 完全没有）、15 秒（Wan 5 秒）、真实感与指令理解最强。

**⚠️ 许可（社区核实）**：MiniMax H3 Community License = **非商用免费**；商用需署名且**过去 12 个月营收 < 2000 万美元**；
**许可排除美国 / 欧盟 / 英国 / 韩国**。⇒ **中国不在排除名单里，二创自用没有问题**。

**16GB 实测数据**（RTX 4060 Ti 16GB + 64GB 内存，中文实测仓库，2026-08-08）：

| 版本 | 模型 | 擅长 | 抽卡档 | 成片档 |
| --- | --- | --- | --- | --- |
| **v1 pruned** | 20.9 GB INT8 | **产品 / 卡通动画**、快节奏抽卡 | 864×480 **~109 秒/条** | 1344×768 ~360s |
| **v2 full** | 34 GB INT8 | **真人 / 写实**、文字特写 | 640×640 ~300s（Sage） | — |

- 加速链：cu130 硬件反量化 + **SageAttention** + T8 双时钟 turbo 8 步 ⇒ 官方 20~30 分钟压到 **3~5 分钟/条**
- ⚠️ **TE-Speed 实测失真，弃用**（唯一可靠加速是 SageAttention）
- 资源：运行时显存 **~14GB** / 系统内存 **~44GB**（仓库标「**32GB 为最低门槛**」）
- 另一路实测（RTX **5070 Ti 16GB**，Z-Image + H3 流水线）：**768×1344 的 10 秒镜头约十几分钟**

**⚠️ 本机硬约束**：你的内存是 **31.7 GB**，正卡在 H3 v2 的最低门槛线上 ⇒ **优先走 v1 pruned（动画向）或 GGUF Q4 档**。

**✅ 本机优势**：你是 **Blackwell（sm_120）**。5090 Laptop 那份 21 组受控实测证明 ——
**NVFP4 是本代卡最佳量化格式：比 INT8 快 22%、小 27%，画质差异落在噪声地板之下**。

### 2.2 出图段：Z-Image-Turbo

| 项 | 结论 |
| --- | --- |
| 定位 | **写实摄影底子**（官方验收记录 excels in photorealistic image generation）；文生图榜开源第 1、总分第 8 |
| 16GB | **官方点名支持档**（bf16 即可，非勉强） |

**⚠️ 重要更正**：**对"纯二次元角色"，它未必打赢你现有的 WAI/Illustrious**
（日本 AICU 八模型同提示词对照：动漫角色完成度上 ANIMAGINE XL 4.0 与 WAI-illustrious 明显更强）。
⇒ **它的价值在"半写实 / 写实"那一档**，不在"更好的纯动画"。

### 2.3 半写实：社区怎么叫、四条路线

**社区术语**（你说的"写实风二次元"不是标准叫法）：**半写实 / 动漫转真人 / 动漫转写实 / Anime 2 Realism**。

| 路线 | 做法 | 适合 |
| --- | --- | --- |
| ① 底模/ LoRA 直出 | 半写实 LoRA、Soft Realism 类 | 最原生 |
| ② 图生图转换 | `Qwen-Image-Edit + AnythingtoRealCharacters2511`（实测**日系动漫转换效果最佳**） | 已有动画图想转写实 |
| ③ **视频段转换** ⭐ | **H3 Ref2VA + `Anime 2 Realism` LoRA（触发词 `LumiReal`）**，自带三种预设：纯写实真人 / 高质量 cosplay 摄影 / 电影级选角 | **最贴合"动漫角色 → 写实电影感动态视频"** |
| ④ 逐帧转换 | LTX 2.3 IC LoRA（ComfyUI 官方工作流「动漫转写实」） | 已有素材整段转 |

**一条必须说的实话**：「电影感」**主要不是模型给的** —— 是**运镜**（H3 有专门运镜 LoRA，12 种训练过的镜头运动）
＋ 光比景深 ＋ 后期颗粒/调色/宽银幕比例 叠出来的。中文教程常拿"换个模型就行"盖掉这一层。

### 2.4 备选档：Wan 2.2 —— 先打预防针

**⚠️ 在 16GB 上，Wan 2.2 的 A14B 基本别想**（三路里最反直觉的一条）：

| 显卡 | 实测 | 来源 |
| --- | --- | --- |
| 4090 24GB | A14B Q5 **480p(832×480)×81 帧 = 316.3s**（峰值 17.3GB）；**720p 只能到 33 帧** | mold 可复现表【实测】 |
| 4090 24GB | A14B fp8 T2V 720p×81 = 4 分 20 秒 | localaimaster【实测】 |
| 5070 Ti 16GB | 作者**直接跳过 A14B FP8** ——「16GB 连 FP8 都装不下，除非激进 offloading」 | 【实测】 |
| 5060 Ti 16GB | **TI2V-5B** fp16 720p×121 帧 20 步 = **541.77s**（9 分钟），峰值 15.77GB | smeltcore【实测】 |
| 4060 Laptop 8GB | 5B fp16 720p×120 帧 = **1180s**（19.7 分钟） | 头条【实测】 |

- **mold 验收记录：「720p 在 24GB 卡上是 5B 的活」**
- ⚠️ **没查到任何 16GB 卡跑 A14B I2V 的实测秒数**（连 480p 都没有）⇒ **16GB 上 A14B 720p 判为不可行（推断）**
- ⇒ **如果非要跑 Wan，就用 TI2V-5B**，别碰 A14B

**Lightning 4 步的真相**（别只听"快 12 倍"）：
- 「2+2 split」= 总步数 4，**高低专家各 2 步**；两个 `LoraLoaderModelOnly` 分别挂 high/low，**不能一个 LoRA 喂两边**；shift=5
- **维护者 X-niper 亲口：「I2V LoRA 比 T2V 好，但仍不如 40 步 base」**
- 社区普遍报**慢动作 / 运动少 / 糊**，且**与分辨率有关**（1280×720 正常，832×480 反而慢动作）

**四个最高频的坑**：
1. ⚠️ **VAE 用错 = 翻车率第一** —— **A14B 用 `wan_2.1_vae`（0.25GB）**，**5B 才用 `wan2.2_vae`（1.41GB）**
2. **页面文件**：实测「20GB pagefile（总 80GB 虚拟内存）时实际用 45GB 却提交 75GB，提交满就 OOM」⇒ **32GB 内存建议固定 64GB 起**（推断值）
3. **SageAttention 会让 Wan 出黑图** ⇒ 用 KJNodes 的 `PatchSageAttentionKJ`（`sageattn_qk_int8_pv_fp16_cuda`）
4. **权重必须放 NVMe** —— 换专家要读盘 10~15GB（冷缓存 8.7~22.2s → 预热 5.6s）

| | ComfyUI | **WanGP（Wan2GP）** | LightX2V |

## 3. 坑清单（社区验证过，按重要性）

1. **【最重要】本地跑 H3 必须自己写官方六段提示词格式** —— 官方网页版/API 前面有个改写器，**本地 ComfyUI 没有这一步**。
   有作者实测：用简短自然语言，模型「几乎原样照抄原片，人没换、字没换」；换成官方六段格式后「同一个镜头一次就换对了」。
   六段：`subject_definitions / summary / retention_analysis / detailed_description / overall_soundscape / non_diegetic_music`。
   配套：**改动一次只加一句**；外观相近时写"对比句"（原片长什么样 → 换成后什么样）。
2. **帧数必须 17k+5**（22 / 73 / 90）—— 硬性要求。
3. **音频 VAE 必须 fp32**，否则音画不同步。
4. **Turbo LoRA 与 EasyCache 二选一，不能同时用**；⚠️ **Turbo 会掉音频质量**（"Audio degrades under Turbo consistently"）⇒
   做法是 **Turbo 出草稿 → 关掉、同种子重跑正片**。
5. **两段式**：草稿 0.2~0.4MP / 8~13 步 → 正片 20~32 步。
6. **CUDA 12.6 → 13 有人把 1MP 5 秒从 20~60 分钟降到 300 秒**（提速巨大，值得上）。
7. **`sol-attn` 无损加速**；⚠️ **SageAttention 在 ≤12GB 反而更慢**。
8. **15 秒以上必须分段续接**；**超 10 秒角色漂移 + 风格断层概率上升**。
9. **一致性**：双人同框开 `input_fidelity=high` 防串脸；不要同一镜头放两个角色正面特写。
10. **各家共同死穴**：快动作、多人互动、**手部特写**、对口型、超 8 秒长镜头。
11. **首尾帧不是万能**：首末帧要在身份/服饰/场景几何/宽高比上兼容；有案例视频编辑试 5 版 SSIM 几乎没变，最后改用首帧图生视频 + 后期溶解。

**⚠️ 笔记本专属两条硬件警告**：
- H3 满载时电脑基本不能用，且社区有 **RTX 4050 Laptop 6GB 显卡物理损坏**的案例（反复重载 75~85°C 后）
- ⇒ **大批量放夜间，加温度墙（85°C）、任务间降温**。⚠️ 你周内 23:30 断电，别排跨夜长队

## 6. 成本账

### 本地侧

| 项 | 数字 |
| --- | --- |
| 满载功耗 | 172 W（GPU 墙，本机实测） |
| 一条 5 秒按 5 分钟算 | ≈ 14 Wh ≈ **0.008 元/条** |
| 抽 100 条 | **≈ 0.8 元** |

真成本是**时间**（一条几分钟~十几分钟）与**硬盘**（H3 + Z-Image 模型 60~70 GB）。

### 闭源侧（只摆事实，不劝买）

**核心公式：实际成本 = 标价 ÷ 成片率** —— 行业拆账（⚠️ 出自标"AI 生成"的聚合稿，数字只作线索）：
一条 10 秒视频，**新手成片率约 5% → 约 200 元/条；老手约 20% → 约 50 元/条**（标价的 5~20 倍）。

标价参考（2026）：可灵 3.0 Omni **0.43 元/秒** ／ 海螺 2.3 **0.93 元/秒** ／ 即梦 Seedance 2.0 VIP **1.38 元/秒**
（另有来源称即梦同规格已从 0.65 → **5.03 元/秒**）／ LibLib 集成可灵高品质 **0.18 元/秒**（最低）。
免费额度：即梦每天 66 积分（≈8s 720p 一条）、可灵每月 128 灵感值（≈14s 720p 一条）。

**行业报价参照**（"仿真人剧"，与"写实风"最贴近）：常规 **1500~8000 元/分钟**，抖音精品漫剧保底 **4000~6000 元/分钟**；
**人力占总成本约 70%**，算力只占小头。

⚠️ **没查到**：本地 vs 闭源的同条件严格对照成本表 —— 任何"本地每月省 X 元"都是推算，不是实测。

### 两条踩坑（已修）

1. **采样器**：作业文件若从 Wan 的 `t2v_settings.json` 抄，`sample_solver` 是 `unipc` ⇒ H3 直接抛
   `ValueError: Unsupported MiniMax H3 sampler 'unipc'`（跑 6 分 49 秒后失败）。**改 `euler`。**
2. **看进度别用管道**：`python wgp.py ... | Select-Object` 会把实时进度全缓冲掉，
   必须 `Start-Process -RedirectStandardOutput <log>` 再轮询日志文件。
